## Oracle and boundaries

`crates/core/tests/classifier_golden.rs` consumes the checked-in
`fixtures/classifier_legacy.json`. Its expectations were generated by **executing
legacy TypeScript**, not by copying Rust results. The generator checks SHA-256
hashes of every runtime source it imports and the original invite fixture before
running. No production implementation, dependency, schema or CI gate is changed.

Source: [TogetherWeOwn/two-bot at
96777468472f23a02a1e97a43ffab3912fe5df2a](https://github.com/TogetherWeOwn/two-bot/tree/96777468472f23a02a1e97a43ffab3912fe5df2a).
The fixture records the full revision and source hashes. This newer revision has
the attribution golden fixture, which does not exist at the frozen parity
revision `d5d1179348feb9157bcac8c875de9399d4f5c76a`. Comparison against the frozen
revision found identical community-classifier and analytics-attribution files;
invite tracker additions are attribution-quality/downtime-report helpers, not
changes to the original growth/window/live algorithms. Join-path additions are
website invite-code parsing/row-source helpers. This corpus does **not** claim to
be an export of tests that were absent at the frozen revision.

The task's `classify.rs` pointer names the **audit-event** classifier. Community
exclusion classification is `community.rs`; attribution is `invites.rs`.
Report CLIs are dropped by `docs/parity.md` §9. A report helper being absent is
not evidence that the separate runtime classifier returns an incorrect result.

## Missing seam: do not substitute classifiers

Legacy `isUnknownBucket` returns true for `unknown` and `backfill:*`; it returns
false for ambiguous, vanity, invite and web sources. The distinct legacy
`attributionCategory` function (and its Next counterpart) returns `other` for
backfill. Using `attribution_category` as the unknown-report helper would test
the wrong contract. The fixture keeps the seven original booleans verbatim and
the inventory identifies six more join-path linkage sites using that helper.

TOG-10973 requests a concrete consuming API or an explicit dropped-report scope
disposition. If a website/runtime consumer still needs it, retain the booleans
and implement/test that consumer on a separate slice. No golden expectation has
been changed to make the port pass.

## Persisted metadata bytes

Attendance expects `{"eventOccurrenceId":"event-1","proof":"host_checkin"}`.
Voice expects keys in **startKnown, startedAt, durationSeconds** order, including
nulls for an unknown start. Both compare raw strings/bytes, not only parsed
object equality. The voice keys are deliberately nonalphabetical, so losing
workspace `serde_json/preserve_order` would be observable. These cases verify
the public serialization helpers; they do not prove database persistence or all
community fact writers. The existing `crates/discord/tests/funnel_replay.rs`
provides a separate 17-row funnel replay corpus; it is not counted again here.

## Reproduce / verify

Export the hash-listed legacy files from the **full pinned revision** into a
run-owned scratch directory using the authorized GitHub broker (`gh api` with
`Accept: application/vnd.github.raw+json`). Keep their repository-relative paths.
Node 24 executes the TypeScript without dependency installation. The generator
uses memory record doubles: no database, Discord, website request or credentials.

```sh
node crates/core/tests/fixtures/generate_classifier_legacy.mjs "$legacy_export" > "$PAPERCLIP_RUN_SCRATCH_DIR/classifier-generated.json"
cmp crates/core/tests/fixtures/classifier_legacy.json "$PAPERCLIP_RUN_SCRATCH_DIR/classifier-generated.json"
```

On a controller with an admitted bounded cache pool and Rust toolchain:

```sh
cargo fmt --all -- --check
python3 scripts/cargo_cache.py run -- test -p two-bot-core --test classifier_golden
```

Do not bypass a refused/missing pool or create another Cargo target. Hosted CI
already discovers this integration test; its normal fmt, clippy `-D warnings`,
workspace tests and cargo-deny gates remain unchanged. Only authorized test
containers/CI service databases may be used by database suites.
